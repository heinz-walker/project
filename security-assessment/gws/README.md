<h1>Google Workspace 보안 현황 점검</h1>
<i>Google Workspace Security Assessment</i>
</div>

*2025.09 · 정보보안 담당*

---

## 1. 요약
Google Workspace(GWS) 사용자 목록과 조직 단위 데이터를 기준으로 인증 현황을 점검했다.
조직 단위별로 2단계 인증 등록률을 나눠 집계해 조직 간 격차를 확인했고, 90일 넘게 미접속한 장기 방치 계정도 다수 찾아냈다.
계정 관리 권한이 조직 단위별로 분리돼 있어 전사 보안 설정 일부는 상위 조직의 협조가 있어야 바꿀 수 있는 구조였기 때문에, 확인된 항목을 조치 권한(자체 조치 가능/상위 조직 협조 필요)별로 나눠 우선순위 보고서로 정리했다.

---

## 2. 배경
인프라 쪽 보안 통제(네트워크, 클라우드 계정, 서버)는 정기적으로 점검해왔지만, 전사 이메일·문서 협업의 기반인 Google Workspace는 SaaS 관리자 콘솔 안에 있어 같은 점검 루틴에 포함되지 않고 있었다.
GWS는 임직원 계정 인증, 문서 공유, 이메일 보안의 기반이 되는 영역이라, 설정 하나의 기본값이 조직 전체의 노출 범위를 바꿀 수 있다.
그래서 이번에 별도로 시간을 내어 관리자 콘솔과 계정 데이터를 점검하기로 했다.

---

## 3. 담당 역할
- 관리 권한 범위 확인 — 계정별 관리 범위와 조직 단위 구조 파악
- 점검 계획 수립 — 권한 범위에 맞춰 자체 조치 가능 항목과 상위 조직 협조 필요 항목을 구분하는 방식으로 설계
- 계정·인증 현황 분석 — 조직 단위별 2단계 인증 등록률, 휴면 계정 집계
- 결과 보고 — 조치 권한별로 항목을 분류해 우선순위 조치안 작성 및 보고

---

## 4. 진행 과정
### 4.1. 관리 권한 범위 확인과 점검 계획 수립
> 계정 관리 권한이 조직 단위별로 분리된 구조를 먼저 확인하고, 그에 맞춰 점검 계획을 짰다.

GWS 관리자 콘솔을 확인한 결과, 이 테넌트는 여러 조직 단위로 구성돼 있고 2단계 인증 강제, 외부 공유 정책, 앱 관리, 감사 로그 같은 전사 보안 설정은 상위 조직 단위에서 관리하는 구조였다.
자사가 속한 조직 단위에서 자체적으로 바꿀 수 있는 범위와, 상위 조직의 협조가 필요한 범위가 나뉘어 있다는 것을 먼저 파악한 뒤, 현재 권한으로 조회 가능한 사용자 목록·조직 단위별 통계부터 분석해 우선순위를 정하는 방향으로 점검 계획을 세웠다.

### 4.2. 조직 단위별 인증 현황 분석
> 조직 단위별로 인증 등록률을 나눠 집계해, 정책 문서로는 드러나지 않던 조직 간 격차와 장기 방치 계정을 찾아냈다.

사용자 목록을 조직 단위별로 나눠 2단계 인증 등록률을 집계한 결과, 조직 단위마다 등록률 편차가 크다는 것을 확인했다 — 특히 자사가 속한 조직 단위의 등록률이 상위 조직 평균보다 뚜렷하게 낮았다.
조직 전체에 2단계 인증을 강제하는 정책 자체가 적용된 계정은 소수에 불과해, 사실상 개인의 자율 등록에 맡겨진 상태라는 것도 함께 확인했다.
로그인 기록은 있으나 90일 넘게 미접속한 계정도 다수 발견했는데, 그중에는 마지막 로그인이 수년 전인 계정도 섞여 있어 퇴사·업무 종료 후 비활성화 처리가 누락된 사례로 추정됐다.

### 4.3. 조치 권한별 결과 보고
> 자체적으로 바로 조치 가능한 항목과, 상위 조직 협조가 필요한 항목을 구분해 보고했다.

점검 결과를 조치 권한 기준으로 나눴다 — 조직 단위 인증 격차와 휴면 계정 목록처럼 현재 권한으로 이미 확인·조치 가능한 항목은 바로 팀 리더에게 공유했고, 2단계 인증 강제 정책이나 외부 공유 설정처럼 조직 전체에 영향을 주는 항목은 상위 조직 협조가 필요하다는 것을 명시해 별도로 정리했다.
권한 범위가 제한된 영역에서도 확인 가능한 범위 안에서 먼저 실행 가능한 결과를 냈다는 점이 이 접근의 핵심이었다.

---

## 5. 성과 및 배운 점
- 조직 단위별 관리 권한 구조를 먼저 파악하고 그에 맞춰 점검 범위를 설계해, 권한이 없는 영역 때문에 점검 전체가 멈추지 않도록 했다.
- 계정 데이터를 조직 단위·최근 로그인 기준으로 집계하는 방식이 정책 문서만으로는 보이지 않는 실제 공백(조직 간 인증 등록률 격차, 장기 방치 계정)을 드러내는 데 효과적이었다.
- 조치 권한별로 항목을 나눠 보고한 덕분에, 자체 조치와 상위 조직 협조가 필요한 부분을 명확히 구분해 각각 실행 가능한 다음 단계를 제시할 수 있었다.
- SaaS 협업도구는 인프라 보안 점검 루틴에 포함되지 않기 쉬운 영역이라는 것을 실제로 확인했고, 이후 정기 점검 대상에 포함하기로 했다.
