## 1. 요약
Stage VPC(`<stage-vpc-cidr>`)에는 이미 [03. Stage 환경 표준 적용 계획](./03-stage-environment-migration-plan.md)에서 다룬 회사 표준 Network Firewall 아키텍처가 적용되어 있었다.
이 표준을 실제로 운영하는 과정에서 배포 경로, 방화벽 정책 평가 순서, 서브넷 구조 세 가지 문제를 발견해 후속 개선을 진행했다.
배포 경로는 운영 서버와 CI/CD 러너가 서비스 서버 6대에 개별 SSH로 접속하던 구조를 배포 서버 1대 경유로 좁혔고, 이 과정에서 보안 그룹 규칙 27건(추가 8건, 제거 19건)을 정리했다.
가장 비중이 큰 작업은 ANFW Suricata 정책의 규칙 평가 순서 문제였다 — 실시간 게임 ALB 접속 장애를 조사하던 중, CIDR 기반 우회 규칙이 STRICT_ORDER 우선순위상 도메인 allow-list보다 먼저 평가되어 목적지가 VPC 내부(ALB)인 트래픽은 도메인 검증 없이 전부 통과되고 있던 구조적 결함을 발견하고 도메인(SNI) 매칭 규칙으로 교체했다.
이어서 시도한 stateless 전환 최적화는 게임 3종 전체의 방입장 장애로 이어져 롤백했고, 이 과정에서 stateful·stateless의 동작 원리 차이를 실제 장애로 검증했다.
마지막으로 internet-facing ALB 12개(NLB 3개 제외)를 전용 서브넷으로 이관해, CIDR을 좁히는 임시 조치 대신 우회 규칙 자체를 완전히 삭제하는 근본 조치까지 마쳤다.

## 2. 배경
[03]에서 적용한 표준 아키텍처는 라우팅과 정책 골격을 갖추는 데 목적이 있었고, Stage는 이 표준이 적용된 뒤에도 실제 운영 과정에서 세 가지 문제가 순차적으로 드러났다.

첫째, 배포 흐름이 표준화 대상에서 빠져 있었다.
운영 서버(admin)와 CI/CD 러너가 각자 서비스 서버 6대에 SSH로 직접 접속하고 있었고, 여기에 bastion에서 특정 고정 IP로 우회 접근하는 경로까지 남아 있어 SSH 진입점이 여러 곳으로 흩어져 있었다.
서비스별 배포 서버를 도입해 이 진입점을 하나로 모아야 감사·롤백·접근 통제가 단순해진다는 문제의식에서 첫 번째 개선이 시작됐다.

둘째, 표준 적용 이후 실시간 게임 서비스의 ALB 접속 장애가 발생했는데, 원인을 추적하는 과정에서 방화벽 정책 자체의 구조적 결함이 드러났다.
ANFW의 도메인 allow-list는 `$HOME_NET → $EXTERNAL_NET` 구조로 설계돼 있어, 목적지가 VPC 내부인 트래픽(우리 ALB로 들어오는 요청)은 애초에 매치될 수 없다는 한계가 있었다.
이 한계를 우회하려고 과거에 걸어둔 CIDR 기반 pass 규칙이, STRICT_ORDER 우선순위상 도메인 allow-list보다 먼저 평가되면서 검증 없는 전체 통과를 만들고 있었다.
이 문제를 파악한 뒤 규칙을 교체하는 것에서 그치지 않고, 같은 방화벽이 흐름 기반 트래픽을 stateless로 다뤘을 때 어떻게 동작하는지도 최적화 시도 과정에서 함께 검증하게 됐다.

셋째, 위 우회 규칙의 근본 원인은 ALB가 NAT Gateway·VPC 엔드포인트·배포 서버와 같은 서브넷에 섞여 있어, 방화벽을 거쳐야 하는 트래픽과 안 거쳐도 되는 트래픽을 서브넷 단위로 분리할 수 없었다는 데 있었다.
우회 규칙의 목적지 CIDR을 아무리 좁혀도 이 섞임 자체는 해결되지 않으므로, 서브넷을 분리해 ALB 트래픽을 방화벽 검사 경로 바깥으로 빼는 근본적인 구조 변경이 필요했다.

## 4. 진행 과정
### 4.1. 배포 흐름 전환
> 운영 서버·CI/CD 러너가 서비스 서버에 개별 SSH하던 경로를 배포 서버 1대 경유로 좁혔다.

기존에는 CI/CD 러너와 운영 서버가 각각 독립적으로 서비스 서버 6대(게이트웨이·게임서버·플레이서버·라우터·메시징·어드민)에 SSH로 직접 접속했고, bastion도 특정 고정 IP를 통해 이 서버들에 직접 접근하는 경로가 남아 있었다.
진입점이 여러 곳(CI/CD 러너, 운영 서버, bastion 고정 IP)으로 흩어져 있으면 배포 이력을 한 곳에서 추적하기 어렵고, 서버 하나가 뚫렸을 때의 영향 범위도 넓어진다는 것이 문제의식이었다.
대안으로는 (1) 기존 구조를 유지한 채 각 진입점의 접근을 세션 로깅으로 보완하는 방법과 (2) 서비스별 배포 서버를 신설해 경로 자체를 단일화하는 방법을 검토했다.
(1)은 진입점 자체가 줄지 않아 감사 대상이 여전히 여러 곳으로 나뉘는 한계가 있었고, (2)는 신규 서버 관리 부담이 늘지만 SSH 경로를 구조적으로 하나로 줄일 수 있어 (2)를 택했다.

배포 서버를 bastion의 점프 서버로도 겸용하도록 설계해, `bastion → 배포 서버 → {서비스 서버 6대, CI/CD 러너}` 하나의 경로만 남기고 기존 직접 경로를 전부 제거했다.
전환 과정에서 예정에 없던 변경 3건(운영 서버의 bastion 고정 IP 우회 경로 제거, 운영 서버의 5개 서비스 직접 SSH 제거, 배포 서버→CI/CD 러너 신규 점프 경로 추가)이 실제 반영된 것을 재조회로 확인했고, 담당자에게 확인한 결과 모두 의도된 변경이라는 것을 확인한 뒤 정리했다.
결과적으로 SSH 진입 주체 2곳(운영 서버, CI/CD 러너)이 서비스 서버 6대에 개별 접속하던 구조가 배포 서버 1대 경유로 수렴됐고, 관련 보안 그룹 규칙 27건(신규 경로 추가 8건, 기존 직접 경로 제거 19건)을 정리했다.

| 구분 | 전환 전 | 전환 후 |
| --- | --- | --- |
| SSH 진입 주체 | 운영 서버, CI/CD 러너, bastion 고정 IP(3개 경로) | 배포 서버 1대 |
| 서비스 서버 도달 경로 | 최대 12개(주체 2 × 서비스 6) 개별 경로 + bastion 직접 | 배포 서버 경유 단일 경로 |
| 관련 보안 그룹 규칙 변경 | - | 27건(추가 8 / 제거 19) |

### 4.2. ANFW 규칙 평가 순서 문제
> CIDR 기반 우회 규칙이 도메인 allow-list보다 먼저 평가되어, ALB로 향하는 트래픽이 도메인 검증 없이 전부 통과되고 있었다.

표준 아키텍처 적용 이후 실시간 게임 서비스(3개 브랜드)의 게이트웨이·게임서버·어드민 ALB 접속 장애가 발생해 원인을 조사했다.
방화벽 정책에는 특정 서버 IP를 하드코딩한 CIDR 기반 pass 규칙이 걸려 있었는데, 대상 서버 IP가 갱신되며 이 규칙이 stale해진 것이 1차 원인이었다.
CIDR을 최신 대역으로 교체해 장애는 일단 해소됐지만, 이 규칙이 애초에 왜 필요했는지를 되짚는 과정에서 더 근본적인 문제를 발견했다.

ANFW의 도메인 allow-list는 `$HOME_NET → $EXTERNAL_NET` 트래픽만 평가 대상으로 하도록 구조화돼 있어, 목적지가 VPC 내부(우리 ALB)인 인바운드 트래픽은 도메인 필드가 아무리 allow-list에 있어도 규칙 구조상 매치될 수 없었다.
이 한계를 우회하려고 과거에 목적지 CIDR 기준 pass 규칙을 별도로 추가해뒀는데, 문제는 이 우회 규칙이 STRICT_ORDER 우선순위 모드에서 도메인 allow-list보다 먼저 평가되는 순번에 있었다는 점이다.
즉 방화벽은 "이 트래픽의 목적지가 우리 ALB(CIDR 범위 내)"라는 것만 확인하면 그 뒤에 있는 도메인 allow-list 규칙까지 가지도 않고 즉시 통과시키고 있었고, 결과적으로 도메인 검증이라는 통제가 이 경로에 한해 완전히 무력화된 상태였다.
이 CIDR 우회 규칙을 제거하는 테스트로 실측 검증했는데, allow-list에 이미 등록돼 있던 정상 도메인(게임 서버 도메인)의 트래픽까지 drop되는 것을 확인해, 도메인 allow-list가 구조적으로 이 트래픽을 매치할 수 없다는 가설을 재확인했다.

대안으로는 (1) CIDR 우회 규칙을 그대로 두되 STRICT_ORDER 순서를 도메인 allow-list 뒤로 조정하는 방법과 (2) CIDR 매치 대신 `tls.sni`/`pcre` 기반으로 허용 도메인을 규칙 자체에 명시하는 방법을 검토했다.
(1)은 우선순위 재조정만으로 해결되는 것처럼 보이지만, CIDR 기반 매치 자체가 "목적지가 우리 ALB"라는 것만 볼 뿐 트래픽의 실제 도메인(SNI)을 전혀 검증하지 않는다는 근본 한계는 그대로 남는다.
(2)는 규칙 자체에 도메인 패턴을 명시해 목적지가 VPC 내부여도 SNI 기준으로 검증하므로, "이 경로는 통제가 아예 안 되는 구조"라는 근본 문제를 해결할 수 있어 (2)를 택했다.
`tls.sni`/`pcre` 기반 도메인 매칭 규칙("ALB 도메인 허용 규칙")으로 교체한 뒤 통신 정상화를 확인했고, 이 검증 과정에서 구조적으로 매치가 불가능했던 것으로 확인된 내부 ALB 도메인 9개를 별도 도메인 allow-list에서 함께 제거 대상으로 정리했다.

이 사건 이후, 같은 방화벽 정책 안에서 반복적인 흐름 기반 TCP 트래픽(메시징·플레이 서버가 쓰는 실시간 프로토콜 허용 규칙)을 stateful rule group에서 stateless rule group으로 옮기는 최적화를 시도했다.
stateless 규칙은 stateful 엔진을 거치지 않아 처리 오버헤드가 적다는 이점이 있어, 반복 트래픽이 많은 구간의 성능을 개선할 수 있을 것으로 판단했다.
요청(목적지 포트 고정)과 응답(출발지 포트 고정) 양방향을 모두 포함하도록 규칙을 구성해 적용했지만, 적용 직후 3개 게임 브랜드 전체에서 방입장 장애가 발생했다.
원인은 stateless pass가 패킷 단위로만 매치를 수행한다는 데 있었다 — 클라이언트가 서버로 보내는 요청 패킷은 고정된 목적지 포트 기준으로 매치되지만, 서버가 클라이언트로 보내는 응답 패킷은 목적지 포트가 클라이언트의 임의 포트라서 별도 매치 조건이 필요했고, 매치되지 않은 패킷은 stateful 엔진으로 그대로 넘어갔다.
stateful 엔진 입장에서는 애초에 추적을 시작한 적 없는 흐름이었으므로, 기본 액션(Drop established)에 걸려 이 응답 패킷들이 조용히 drop되고 있었다.
즉 stateful pass는 흐름(flow) 단위로 한 번 허용하면 왕복 패킷을 자동으로 같은 흐름으로 추적하지만, stateless pass는 패킷 단위 규칙이라 양방향 흐름을 스스로 따라갈 방법이 없다는 것을 장애로 실측한 셈이다.
이 원리를 확인한 뒤 stateless 쪽 규칙을 제거하고 기존 stateful 허용 규칙("실시간 프로토콜 허용 규칙")을 재연결해 원상복구했고, "흐름 기반 TCP 프로토콜은 stateless로 옮기지 않는다"는 원칙을 정리했다.

| 구분 | 문제 | 원인 | 조치 |
| --- | --- | --- | --- |
| ALB 접속 장애 | 도메인 allow-list 무력화 | CIDR 우회 규칙이 STRICT_ORDER상 allow-list보다 먼저 평가됨 | `tls.sni`/`pcre` 도메인 매칭 규칙으로 교체 |
| stateless 최적화 시도 | 게임 3개 브랜드 방입장 장애 | stateless pass가 패킷 단위라 양방향 흐름을 못 따라감 | stateful 규칙으로 롤백 |

### 4.3. ALB·NLB 전용 서브넷 분리
> 우회 규칙의 목적지 범위가 필요 이상으로 넓었던 문제를 서브넷 분리로 근본 해결했다.

4.2에서 교체한 도메인 매칭 규칙에도 근본 한계가 있었다 — 이 규칙의 목적지 CIDR이 기존 public 서브넷(`<stage-public1-cidr>`, `<stage-public2-cidr>`) 전체였고, 이 서브넷에는 ALB뿐 아니라 NAT Gateway, VPC 인터페이스 엔드포인트, 배포 서버까지 같이 있었다.
즉 방화벽을 반드시 거쳐야 하는 트래픽(NAT·엔드포인트·배포 서버 아웃바운드)과 방화벽 통제가 사실상 무의미한 트래픽(ALB 인바운드)이 같은 서브넷, 같은 우회 규칙의 영향권에 섞여 있었다.
대안으로는 (1) 우회 규칙의 목적지 CIDR을 ALB가 쓰는 IP 대역만으로 더 좁히는 방법과 (2) internet-facing ALB를 전용 서브넷으로 옮겨 우회 규칙 자체를 삭제하는 방법을 검토했다.
(1)은 ALB가 늘거나 IP가 바뀔 때마다 규칙을 계속 수동으로 맞춰야 하고, 서브넷을 공유하는 한 NAT·엔드포인트·배포 서버 트래픽과 뒤섞이는 구조 자체는 남는다는 한계가 있었다.
(2)는 서브넷을 완전히 분리하면 "우회 규칙이 왜 필요한가"라는 질문 자체가 사라지므로, 규칙을 좁히는 대신 아예 삭제하는 (2)를 최종 방향으로 택했다.

신규 서브넷 2개(AZ별 1개, `<stage-alb-public1-cidr>`/`<stage-alb-public2-cidr>`)를 만들어 라우팅을 방화벽 엔드포인트가 아닌 IGW로 직결했고, 인바운드 방향의 IGW ingress 라우팅에도 이 신규 CIDR을 등록하지 않아 인바운드·아웃바운드 양방향 모두 방화벽을 거치지 않는 대칭 구조로 맞췄다.
ALB는 스스로 먼저 나가는 연결을 만들지 않고 인바운드만 받는 역할이라, 방화벽을 거치지 않아도 잃는 것은 SNI 기반 도메인 필터링뿐이라고 판단했고, 이 필터링은 애초에 실질적인 보안 통제라기보다 도메인 allow-list의 구조적 한계를 메우던 우회 장치였다는 점에서 감수할 수 있는 트레이드오프로 봤다.
NAT Gateway, VPC 엔드포인트, 배포 서버는 서브넷 이동이 불가능하거나 이동할 이유가 없어 기존 서브넷에 그대로 남겼고, 이 서버들은 계속 방화벽 검사와 도메인 allow-list의 정상 적용 대상으로 유지했다.
internet-facing ALB 12개(NLB 3개는 내부 통신용이라 이관 대상에서 제외)를 게임 브랜드 단위로 끊어서 순차 이관했고, 이관마다 대상 그룹 헬스체크·실통신·방화벽 alert 로그(새 서브넷 트래픽이 잡히지 않아야 정상)를 확인한 뒤 다음 브랜드로 넘어갔다.
전체 이관을 마친 뒤 우회 규칙을 정책에서 연결 해제하고 규칙 자체를 삭제해, CIDR을 좁히는 임시 조치가 아니라 우회 규칙이 필요 없는 구조로 전환을 완료했다.

## 5. 성과 및 배운 점
- SSH 진입 주체 2곳·최대 12개 직접 경로를 배포 서버 1대 경유로 수렴하고, 관련 보안 그룹 규칙 27건(추가 8 / 제거 19)을 정리했다.
- ANFW STRICT_ORDER 우선순위상 CIDR 우회 규칙이 도메인 allow-list보다 먼저 평가되어 발생한 검증 무력화 문제를 발견하고, 도메인(SNI) 매칭 규칙으로 교체해 실시간 게임 ALB 3개 브랜드의 접속 장애를 해소했다.
- 같은 조사 과정에서 구조적으로 매치 불가능했던 내부 ALB 도메인 9개를 도메인 allow-list에서 함께 정리했다.
- stateless 전환 최적화 시도와 롤백을 통해 "stateful pass는 흐름 단위로 왕복을 자동 추적하지만 stateless pass는 패킷 단위라 양방향 흐름을 스스로 따라가지 못한다"는 원리를 실제 장애로 검증했고, 이는 이후 어떤 트래픽을 stateless로 옮길 수 있는지 판단하는 재사용 가능한 기준이 됐다.
- ALB·NLB 12개를 전용 서브넷으로 분리해, 우회 규칙의 목적지 범위를 좁히는 임시 조치 대신 규칙 자체를 완전히 삭제하는 근본적인 구조 개선을 완료했다.
- 세 작업 모두 "규칙을 조정한다"가 아니라 "왜 이 규칙이 이렇게 동작하는가"를 먼저 확인한 뒤 대안을 비교했고, 이 접근이 재발을 막는 데 CIDR 조정 같은 임시방편보다 더 효과적이었다.
