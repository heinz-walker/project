## 1. 요약
[01. Network Firewall·NAT Gateway 비용 구조 분석](./01-nat-firewall-cost-structure.md)에서 방화벽 비용의 대부분이 트래픽과 무관한 엔드포인트 고정 요금임을 확인했다.
이를 바탕으로 상시 트래픽이 필요 없는 Dev 환경의 방화벽을 켜 두는 비용과, 운영 방식을 바꿨을 때의 절감 범위를 계산했다.
Dev 방화벽을 켜 둔 비용의 98.6%가 엔드포인트 시간당 요금이고, 트래픽 처리와 로그를 합쳐도 1.4%다.
여기서 "끈다"는 라우팅 우회 후 엔드포인트를 삭제하고, 켤 때 같은 설정으로 다시 만드는 것을 뜻한다. 한 달 내내 끄면 켜 둔 비용의 약 85%를, 월 22일 × 일 10시간만 켜면 약 60%를 줄일 수 있다. 로그만 줄이면 약 1%에 그친다.
끄면 NAT 요금 면제도 함께 사라지므로, 절감액은 방화벽 비용이 아니라 되살아나는 NAT 요금을 뺀 순절감으로 계산했다.

---

## 2. 배경
01번 분석의 결론은 방화벽 비용을 줄이려면 엔드포인트를 켜 두는 시간을 줄이는 수밖에 없다는 것이었다.
Dev는 실서비스 트래픽이 없고 필요할 때만 쓰는 환경이라, 항상 켜 둘 이유가 가장 약하다.
다만 "끄면 방화벽 비용만큼 아낀다"는 계산은 틀린다. 방화벽이 꺼지면 NAT가 방화벽과 같은 경로가 아니게 되어 면제가 사라진다.
정확한 절감액을 알아야 끄는 운영을 결정할 수 있고, 로그를 줄이는 쪽이 대안이 될 수 있는지도 확인해야 했다.

---

## 3. 담당 역할
- Dev 방화벽 비용 항목 분해(엔드포인트, 트래픽 처리, 로그 수집·저장, 대시보드 조회)
- 방화벽·NAT 트래픽과 로그 수집량 31일 실측
- 운영 방식별 시나리오 비교와 보안 트레이드오프 정리

## 4. 진행 과정
### 4.1. 비용 항목 분해 — 어느 항목이 얼마인지부터
> 방화벽 비용을 다섯 항목으로 나눠 각각의 단가와 실측량을 확인했다.

비용을 엔드포인트 시간당, 트래픽 처리, 로그 수집, 로그 저장, 대시보드 조회로 나눴다.
단가는 서울 리전 공식 단가이고, 로그는 방화벽 로그에 적용되는 vended logs 단가를 썼다.
로그 수집량 구간은 계정 전체 합산 기준인데, 이 계정은 첫 구간 안이라 가장 높은 단가가 적용된다.
대시보드는 켜 두기만 해서는 비용이 들지 않고, 콘솔에서 조회할 때마다 로그 그룹을 쿼리하므로 그때 스캔 비용이 든다.

CloudWatch 지표로 31일간 Dev 방화벽과 NAT 처리량, 로그 수집량과 저장량을 실측했다.
Dev 라우팅 테이블에서 NAT 요금 면제 조건을 다시 확인했고, 방화벽 처리량이 NAT 처리량보다 크고 엔드포인트 수도 같아서 NAT 요금은 전액 면제 대상이다.

항목별 결과는 다음과 같았다.

| 항목 | 비중 |
| --- | ---: |
| 엔드포인트 시간당 | 98.6% |
| 트래픽 처리 | 0.2% |
| 로그 수집 | 1.2% |
| 로그 저장 | 0.02% |

로그 수집량은 방화벽 처리량의 64%로 트래픽에 비해 많았지만 금액 자체는 작았다.
일별 추이를 보면 수집량이 계속 줄고 있었는데, 정책 분리 작업 시기와 겹치지만 원인은 확인하지 않았다.
로그 저장은 압축 후 기준이라 보존 기간을 줄여도 아낄 금액이 거의 없다.

### 4.2. 시나리오 비교 — 끄면 NAT 요금이 되살아난다
> 방화벽을 끄면 면제가 사라지므로, 절감은 방화벽 비용이 아니라 순절감으로 계산했다.

먼저 "끄기"를 정의했다. 방화벽은 일시정지가 없고, 엔드포인트는 프로비저닝된 동안 시간당 요금이 붙는다. 라우팅만 우회하고 엔드포인트를 두면 고정비가 그대로 나간다.
그래서 이 시나리오의 끄기는 라우팅 우회 후 엔드포인트 삭제이고, 켜기는 같은 설정으로 재생성한 뒤 경로를 복원하는 것이다. 정책, 규칙 그룹, 로그 그룹은 유지한다.

744시간 기준으로 네 가지 운영 방식을 비교했다. 켜 둔 비용을 100으로 놓았다.

| 시나리오 | 비용(켬 = 100) | 절감 |
| --- | ---: | ---: |
| A. 항상 켬(현재) | 100 | – |
| B. 한 달 내내 끔 | 15 | 85% |
| C. 평일 업무시간만 켬 | 40 | 60% |
| D. 켜 두고 로그만 끔 | 99 | 1% |

B에서는 방화벽 비용이 사라지는 대신 NAT 시간당 요금과 처리 요금이 그대로 청구된다.
그래서 절감은 방화벽 비용에서 되살아난 NAT 요금을 뺀 값이다.
C는 월 22일, 일 10시간(월 220시간) 가동을 가정했고, 트래픽과 로그 비용이 켜 둔 시간 비율만큼 비례한다고 본 추정이다. 업무시간에 트래픽이 몰리면 변동비가 조금 더 크지만 총액 차이는 작다.
같은 방식으로 일 8시간(월 176시간)이면 약 65%, 상시 off면 약 85%다. 절감률은 (1 − 가동시간/744) × (1 − NAT 시간당 단가/방화벽 시간당 단가)로 고정비만 대조한 값이다.
켜기에는 엔드포인트 재생성 완료를 기다려야 해서, 업무 시작 전에 미리 켜 두면 실제 가동시간은 이 가정보다 늘어난다.

켜 둔 시간 1시간당 차이는 2 × ($0.395 − $0.059) = $0.672다.
방화벽 시간당 요금에서, 켜 있을 때 면제되는 NAT 시간당 요금을 뺀 값이다.
이 단위로 어떤 운영 방식이든 절감액을 바로 계산할 수 있어서, 켜 두는 시간을 얼마나 줄일지를 정책으로 정할 수 있다.
D가 보여 주듯 로그만 줄이는 쪽은 비용 관점에서 선택지가 아니다.

### 4.3. 보안 트레이드오프 — 비용 결정과 분리
> 끄는 동안의 보안 공백은 비용 계산과 별개로 판단해야 해서, 이 보고서에서 결정하지 않았다.

방화벽이 꺼져 있는 동안 Dev 아웃바운드는 도메인 allowlist 필터링 없이 나가고, alert와 flow 로그도 남지 않는다.
Dev가 실서비스 데이터를 다루지 않는다는 전제에서만 받아들일 수 있는 공백이다.
비용만 보면 B가 가장 낫지만 C가 보안 공백 시간을 줄이면서도 절감 폭이 크다.
결정은 Dev의 데이터 성격과 필요한 로그 보존 요건을 가진 쪽에서 해야 해서, 선택지와 수치까지만 제시하고 남겼다.

## 5. 성과 및 배운 점
- Dev 방화벽 비용의 98.6%가 엔드포인트 시간당 요금임을 항목 분해로 확인했다. 로그와 트래픽은 합쳐서 1.4%여서 줄여도 의미가 없다.
- "끄면 방화벽 비용만큼 아낀다"가 아니라 면제 소멸을 반영한 순절감 85%(상시 off)와 60%(업무시간만 on)라는 범위를 제시했다.
- 켜 둔 시간 1시간당 $0.672라는 단위를 만들어, 운영 방식별 절감액을 계산 없이 비교할 수 있게 했다.
- 로그 그룹 하나의 보존 기간이 무기한으로 설정된 것을 발견했다. 지금은 금액이 작지만 정리 대상이다.
- 한계: 실제 청구액과 대조하지 못했다. 시나리오 C의 변동비는 가정에 기반한 추정이다.
- 후속 과제: 방화벽 일괄 on/off 자동화(끄는 순서와 같은 설정으로 다시 켜는 순서를 단계별 스크립트로 분리), 끄는 방식의 보안 요건 결정, 엔드포인트를 1개 AZ로 줄이는 대안의 비용과 가용성 비교.
