## 1. 요약
연 1회 의무 정보보안 교육을 문서·슬라이드 배포가 아니라 브라우저에서 실제로 동작하는 인터랙티브 웹앱으로 만들었다.
5개 챕터(사회공학, 비밀번호·계정, 매체 제어, CLEAN PC·DESK, Wi-Fi)로 구성했고, 각 챕터는 개념 설명 + 실습 요소 + 퀴즈로 이어지며 퀴즈를 통과해야 챕터가 이수 처리된다.
실습 요소로는 4종의 모의 피싱 메일 구분 테스트(악성 3종·정상 1종), 의심 링크 클릭 시 가짜 로그인 화면이 뜨는 피싱 시뮬레이션, 입력값을 저장하지 않는 실시간 비밀번호 강도 측정기(5개 규칙), 챕터별 OX·객관식 퀴즈 9문항, 진행률 추적(0/5), 수료증 발급, 5점 척도 만족도와 자유 서술 피드백 수집을 넣었다.
프런트엔드는 프레임워크 없이 단일 HTML/CSS/JS로 작성했고, 백엔드는 Google Apps Script로 페이지 서빙과 이수·피드백 데이터의 스프레드시트 적재를 처리해 별도 서버 없이 사내에 배포했다.

---

## 2. 배경
기존 정보보안 교육은 정책 문서와 슬라이드를 배포하고 열람 여부에 서명을 받는 방식이었다.
이 방식으로는 자료를 끝까지 봤는지, 내용을 이해했는지, 실제 상황에서 다르게 행동할지를 전혀 확인할 수 없었다.
특히 사회공학·피싱은 "이런 메일을 조심하라"는 설명을 읽는 것과, 실제로 의심스러운 메일을 열어 링크를 눌러보고 가짜 로그인 화면까지 마주하는 것 사이에 학습 효과 차이가 크다.
그래서 이번 교육은 "자료를 봤다"가 아니라 "실습을 해봤고 퀴즈를 통과했다"를 이수 기준으로 삼고, 교육이 끝난 뒤에는 수강자 피드백을 모아 다음 회차를 개선하는 구조로 다시 설계했다.

---

## 3. 담당 역할
- 교육 콘텐츠 설계 — 5개 챕터의 개념·실습·퀴즈 구성, 사내 보안정책(비밀번호 복잡도, 매체 제어 승인 절차, CLEAN PC·DESK 점검 항목, Wi-Fi 이용 수칙)을 교육 항목으로 정리
- 인터랙션·실습 요소 구현 — 모의 피싱 메일 구분 테스트, 피싱 클릭 시뮬레이션, 비밀번호 강도 측정기, 챕터별 퀴즈와 즉시 피드백, 진행률 추적, 수료증 발급을 단일 HTML/CSS/JS로 개발
- Apps Script 백엔드 구현 — 페이지 서빙, 이수 정보·별점·피드백의 스프레드시트 수집, 이수 리포트 무결성 검증
- 배포 및 피드백 수집·정리 — 사내 배포, 수집된 만족도·서술 피드백 분석

## 4. 진행 과정
### 4.1. 교육 콘텐츠 설계
> 챕터를 "읽는 자료"가 아니라 "개념 → 실습 → 퀴즈"의 한 묶음으로 설계하고, 퀴즈 통과를 이수 조건으로 걸었다.

교육 범위는 그해 사고·문의가 잦았던 영역과 ISMS 필수 항목을 기준으로 5개 챕터로 좁혔다.
사회공학은 공격자가 노리는 심리 트리거 7종(긴급성·권위·호의/보상·호기심·두려움·일관성/신뢰·사회적 증거)을 예시와 함께 제시하고, 비밀번호·계정은 사내 복잡도 정책과 MFA를, 매체 제어는 전자결재와 엔드포인트 보안 솔루션(DLP·PC 보안점검 통합) 승인이 별개 단계라는 점을, CLEAN PC·DESK는 분기 점검 체크리스트를, Wi-Fi는 공식 SSID 2종과 공용망 이용 수칙을 다뤘다.
각 챕터에 개념 설명만 두면 결국 "스크롤 후 서명"과 다를 게 없어서, 챕터마다 그 내용을 직접 써보게 하는 실습이나 퀴즈를 배치하고, 이것을 통과하기 전에는 챕터가 이수 처리되지 않도록 했다.

### 4.2. 인터랙션·실습 요소 구현
> 설명으로 전달되지 않는 부분(피싱 메일의 의심 신호, 클릭 이후 벌어지는 일, 약한 비밀번호의 실체)을 직접 조작해보게 만들었다.

공개용 버전은 [인터랙티브 데모](https://heinz-walker.github.io/project/security-training/)로 직접 실행해 볼 수 있고, 익명화한 전체 코드는 [소스](./code/)에 있다.

구현한 실습 요소와 설계 의도는 다음과 같다.

| 요소 | 내용 | 설계 의도 |
| --- | --- | --- |
| 모의 피싱 메일 구분 테스트 | 악성 3종·정상 1종의 메일을 실제로 열어 보고 발신 주소·본문·첨부·링크를 보고 악성/정상을 판정 | 의심 신호를 목록으로 외우는 대신 실제 메일에서 찾아내게 함 |
| 피싱 클릭 시뮬레이션 | 메일 속 의심 링크를 누르면 가짜 로그인 화면이 뜨고, 정보를 입력하면 경고가 표시됨 | "링크를 누르면 무슨 일이 벌어지는가"를 안전한 환경에서 체험 |
| 비밀번호 강도 측정기 | 입력과 동시에 길이(8–20자)·소문자·대문자·숫자·특수문자 5개 규칙 충족 여부를 실시간 표시, 입력값은 저장하지 않음 | 자기 비밀번호로 바로 확인하되 수집 우려는 없게 함 |
| 챕터별 OX·객관식 퀴즈 | 매체 제어·보안점검·Wi-Fi 챕터에 3문항씩, 오답 시 즉시 해설 | 이수 여부를 열람이 아니라 정답으로 판정 |
| 진행률·수료증 | 5개 챕터 완료 시 수료증 발급, 소속·성명·이메일 입력 | 이수 증빙을 자동화 |

피싱 클릭 시뮬레이션의 가짜 로그인 화면은 사내 배포판에서는 임직원이 실제로 자주 쓰는 쇼핑몰 로그인 페이지를 복제해 현실감을 높였다.
공개용 포트폴리오 버전에서는 이 부분을 특정 브랜드가 없는 "OO몰 로그인" 수준의 일반화된 목업으로 대체하고, 화면 상단에 원래는 실제 페이지 복제본이었다는 안내 배너를 넣었다.
의심 링크 클릭 → 가짜 로그인 화면 등장 → 경고로 이어지는 학습 흐름 자체는 그대로 유지했다.

### 4.3. Apps Script 백엔드
> 별도 서버·인프라 없이 배포하기 위해 백엔드를 Google Apps Script로 두고, 페이지 서빙과 데이터 수집만 처리했다.

`doGet`이 요청 파라미터에 따라 교육 본문(index)이나 실습용 목업 페이지를 서빙하고, `iframe` 임베드를 허용하도록 X-Frame-Options를 설정한다.
수료 시 클라이언트가 `google.script.run`으로 소속·성명·이메일·별점·서술 피드백을 전달하면, 백엔드가 이수 스프레드시트에 타임스탬프와 함께 한 행으로 적재하고 중복 이수를 걸러낸다.
이수 리포트에는 위변조를 막기 위해 무결성 검증(HMAC 서명)을 붙였다.
공개용 소스(`code/`)에서는 스프레드시트 ID를 `<YOUR_SPREADSHEET_ID>`로 바꾸고, 특정 쇼핑몰 페이지를 서빙하던 로직을 일반 목업 서빙으로 주석 처리했다.
공개 데모 HTML은 이 백엔드가 없어도 동작하도록, `google.script`가 없으면 클라이언트에서 바로 수료 UI를 띄우고 피드백은 `localStorage`에만 저장하는 폴백을 넣었다.

## 5. 성과 및 배운 점
- 이수 기준을 "자료 열람 + 서명"에서 "실습 수행 + 퀴즈 통과"로 옮겼다. 5개 챕터 각각에 통과 조건(피싱 메일 4종 전부 정답, 비밀번호 5개 규칙 충족, 챕터 퀴즈 3문항 정답)을 걸어, 스크롤만으로는 수료증이 발급되지 않게 했다.
- 수료 단계에서 5점 척도 만족도와 자유 서술 피드백을 함께 수집해, 다음 회차 콘텐츠 개선의 근거로 쓸 수 있는 피드백 루프를 만들었다.
- 프레임워크 없는 단일 HTML/CSS/JS와 노코드 성격의 Apps Script만으로 별도 서버 없이 사내 배포까지 마쳤다. 인프라 요청·검토 없이 빠르게 만들고 고칠 수 있었다.
- 피싱 실습은 현실감이 클수록 학습 효과가 크지만, 실제 로그인 페이지 복제본은 그대로 외부에 공개할 수 없다. 사내 배포판과 공개 포트폴리오 버전을 분리하고, 공개 버전은 학습 흐름을 유지하되 브랜드 의존성과 외부 요청을 제거해야 했다.
